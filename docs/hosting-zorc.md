# Hosting ThorMCP on the zorc platform

ThorMCP can be hosted as a **remote streamable-HTTP MCP server** on the
[zorc](https://mcp.zaindroid.me) deployment platform. Any MCP client
(Claude Desktop, Codex, Cursor, opencode, ...) can then connect to the
hosted endpoint with just a URL + bearer token — exactly like the
remote MCP servers you already run.

## How it works

zorc deploys from a GitHub repo. It inspects the repo, checks your
declared requirements against the actual code, provisions a database if
declared, then runs your container behind Traefik (no host ports).

The repository is already contract-compliant:

| Contract item | Where it's satisfied |
| --- | --- |
| `app.yaml` manifest | `deploy/app.yaml` |
| `GET /health` | `thor_mcp/deploy.py` — `{"status": "ok"}`, never touches the DB |
| `GET /ready` | `thor_mcp/deploy.py` — probes `DATABASE_URL` when set |
| `GET /version` | `thor_mcp/deploy.py` — reads `THOR_BUILD_SHA`/`THOR_BUILD_TIME` |
| `GET /openapi.json` | provided by FastAPI automatically |
| JSON logs to stdout | `thor_core.logging` switches to JSON stdout when `APP_ENV` is set |
| Fail loudly on missing env | `ThorMCPServer` requires `MCP_SECRET_KEY` when `APP_ENV=production` |
| No secrets in repo | secrets are `GENERATE_ME` entries in `app.yaml` |
| Database provisioning | `database: true` in `app.yaml`; `BenchmarkStore` reads `DATABASE_URL` |

## Deploy steps

1. Push this repo to GitHub (private or public).

2. In any MCP client, run zorc's analysis tool against the repo URL —
   required before deploy:

   ```
   analyze_deployment_requirements()  →  report_id
   ```

   zorc clones the repo, cross-checks `deploy/app.yaml` against the
   code, and approves or tells you exactly what to fix.

3. Deploy with the report id. `THOR_TOKEN` and `MCP_SECRET_KEY` are
   generated by zorc itself (declared as `GENERATE_ME`); nothing else
   is needed:

   ```
   deploy(report_id)
   ```

4. Connect to the hosted server. The MCP endpoint is
   `https://<domain>/mcp`:

   ```json
   {
     "mcpServers": {
       "thor": {
         "url": "https://mcp.thor.zaindroid.me/mcp",
         "headers": { "Authorization": "Bearer <THOR_TOKEN>" }
       }
     }
   }
   ```

   Note: `THOR_TOKEN` is generated at deploy time — you'll find it in
   zorc's deploy output or ask whoever runs `deploy()`.

## Verifying against the live endpoint

The `ThorMCPClient` connects to any streamable-HTTP MCP endpoint:

```python
import asyncio
from thor_mcp.client import ThorMCPClient

async def main():
    async with ThorMCPClient(
        url="https://mcp.thor.zaindroid.me/mcp",
        headers={"Authorization": "Bearer <THOR_TOKEN>"},
    ) as client:
        print(await client.list_tools())

asyncio.run(main())
```

## Local test server

```bash
thor-mcp --http-mcp --port 8000
# MCP endpoint:  http://localhost:8000/mcp
# health:        http://localhost:8000/health
# ready:         http://localhost:8000/ready
# version:       http://localhost:8000/version
```

## Leaderboard hosting (optional)

The leaderboard API (`website/backend`) is a FastAPI app with the same
contract endpoints. A second manifest example lives at
`deploy/app-leaderboard.yaml`; it declares `database: true` for
`benchmark_runs` persistence.
