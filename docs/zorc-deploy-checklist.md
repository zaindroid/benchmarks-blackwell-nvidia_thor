# Zorc Deploy Checklist (Path A)

ThorMCP is deployment-ready for the zorc platform. This checklist is
what to run the moment the repo is on GitHub. The `deploy/` manifest,
contract endpoints, and storage are already in place — see
[docs/hosting-zorc.md](hosting-zorc.md) for the full contract mapping.

## Prerequisite (your action)

1. Create an empty GitHub repo (e.g. `zaindroid/thor-ai-platform`).
2. Run the push script (or give me the repo URL and I'll run it):

   ```bash
   REPO=zaindroid/thor-ai-platform ./tools/scripts/push-to-github.sh
   ```

3. Send me the URL (e.g. `https://github.com/zaindroid/thor-ai-platform`).

## Then (I run these against your zorc endpoint)

With the repo URL, these calls go through `ThorMCPClient` against
`https://mcp.zaindroid.me/mcp` with your bearer token:

### 1. Analyze (required before deploy)

```python
report = await client.call_tool("analyze_deployment_requirements", {
    "repo": "https://github.com/zaindroid/thor-ai-platform",
})
report_id = report["report_id"]   # or the report will state what to fix
```

zorc clones the repo, cross-checks `app.yaml` against the
actual code, and either approves or returns the specific blockers
(e.g. memory estimate, missing endpoint, undeclared env var). Fixes
typically land in `app.yaml` or the server entrypoint.

### 2. Deploy

```python
result = await client.call_tool("deploy", {
    "report_id": report_id,
})
# zorc derives memory/node placement from the report; THOR_TOKEN and
# MCP_SECRET_KEY are generated by zorc (GENERATE_ME entries) and set
# before the container's first real start.
```

### 3. Verify

```bash
# From any MCP client:
curl -s https://mcp.thor.zaindroid.me/health    # {"status": "ok"}
curl -s https://mcp.thor.zaindroid.me/ready     # 200 once DB reachable
curl -s https://mcp.thor.zaindroid.me/version   # {"sha": ..., "built": ...}
```

```json
{
  "mcpServers": {
    "thor": {
      "url": "https://mcp.thor.zaindroid.me/mcp",
      "headers": { "Authorization": "Bearer <THOR_TOKEN from deploy>" }
    }
  }
}
```

## Expected analyze findings (heads-up)

- `database: true` in `app.yaml` → zorc provisions Postgres and
  sets `DATABASE_URL`; `BenchmarkStore` already reads it, and
  `/ready` probes it.
- `MCP_SECRET_KEY` is declared `GENERATE_ME` → generated, and the
  server fails loudly (per the contract) if it's ever missing.
- The deployable is the streamable-HTTP MCP server
  (`thor-mcp --http-mcp`), port 8000, no host port binding.

## Troubleshooting: `add_tunnel_route` failure (observed 2026-08-18)

Deploy failed at step `add_tunnel_route`:

```
Command '['sudo', 'cp', '/home/zman/zorc/cloudflared/config.yml',
'/etc/cloudflared/config.yml']' returned non-zero exit status 1.
```

Server-side issue on the zorc host (the repo/app manifest were fine —
analyze was approved, `database_provisioned: true`,
`MCP_SECRET_KEY`/`THOR_TOKEN` generated internally). The app is **not
registered** after this failure, so retrying is safe. Fix on the zorc
host, as the `zman` user:

```bash
ls -la /home/zman/zorc/cloudflared/config.yml      # source exists?
sudo -n cp /home/zman/zorc/cloudflared/config.yml /etc/cloudflared/config.yml
# "a password is required" -> grant passwordless sudo for cp:
echo "zman ALL=(ALL) NOPASSWD: /usr/bin/cp" | sudo tee /etc/sudoers.d/zorc-cloudflared
# /etc/cloudflared missing:
sudo mkdir -p /etc/cloudflared && sudo chown zman /etc/cloudflared
```

Then re-run `analyze_deployment_requirements` (the report id expires
after 60 min) and `deploy()` again.
